# 泉廊便民 · 公共饮水点除垢工时预算

估算每处饮水点的停用工时，按优先级给下一班预留维修时间。

模拟团队为 泉廊便民设施运维组，9 人轮值，服务 24 个街区便民站。。巡检员抄录机型、维护间隔和现场水垢分级，排班员从上月完工工单中挑相似案例，按估计时长手工填写停用公告与班次交接单。

- 相同垢级在不同出水口构型上的工时差异大。
- 交班表只写平均时间，班次末端容易欠下未完工项目。
- 个别点位体量大且替代点远，按报修先后会推迟优先点位。

现场巡检台账与完工工单。历史样本记录从设备停用到恢复开放的实际用时，计划样本只录排班前已知的现场条件。 排班员按序确认工作队列，站点联系人根据工时预留发布暂时停用信息，班组回填实际用时。

## 业务模块

| 模块 | 工作内容 | 核心实体 |
|---|---|---|
| 点位巡检与完工台账 | CSV 校验、预览实测字段、以完整数据内容的 SHA-256 去重、追溯版本和下载原始数据 | 数据版本 |
| 班次工时预算 | 按版本与领域参数创建计算单，由独立进程计算；从排队、成功或失败状态追溯 | 计算单 |
| 停用预留顺序 | 按业务字段查看度量、比较与排序，下载计算结果 | 计算单及其结果 |
| 设施维修交接 | 对结果样本作签发或暂缓，记录理由，导出选中样本并查看审计时间线 | 交接记录 |

## 算法及口径

**梯度提升回归 · 留出误差校准与班次分配**。训练工单用机型、出口数、距上次维护天数、维护前硬度档、目视垢级和是否需登记进场拟合直方图梯度提升回归。中心预测以分钟计。校准集按真实分钟减中心预测排序，取 ceil((样本量 + 1) × 0.90) 对应残差，保留非负缓冲量，得到单个点位的 90% 校准工时上界，向上取整后占用班次。独立核验集计算 MAE 与上界覆盖。计划按核定优先级、维护间隔和单号排序，累加预留分钟，第一个无法排入的点位与其后续点位转到下一班。历史缺时长、计划行填入实际时长、训练或留出样本不足时需修正台账。

录入参数 **本班可用分钟**，默认 210，允许范围 30–720。填写已经扣除交通、交接和其他巡检工作的维修时间。

演示集 `QL-1125-街区设施停用预留.csv` 由 `backend/src/business/demo.py` 用固定数据或固定随机种子生成。工作台保留每次运行使用的输入版本、参数、结果和签审人。业务判断由服务端执行，前端图表直接读取返回的数值。

## 一天的工作剧本

1. 08:30 汇入 QL-1125-街区设施停用预留.csv，确认有训练、校准、核验三组完工记录和 8 个待派点位。
2. 08:45 核对 QL-P01 槐行广场西侧：落地式、3 个出口、距上次维护 145 天，垢级 4。
3. 09:00 以工程师账号创建本班预算，预留可用 210 分钟。
4. 09:05 核对独立留出 MAE 与覆盖口径，比较 QL-P01 和 QL-P06 的预留分钟。
5. 09:10 在处置顺序中确认高优先级 QL-P01 优先入班，检查后续转下班点位。
6. 09:15 导出设施维修交接表，交班员复核各点预留时间和剩余分钟。
7. 13:30 站点联系人按交接单确认停用窗口，班组完工后回填实际时长。

```sh
test -f .env || cp .env.example .env
docker compose config --quiet
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

## 技术与配置

| 服务 | 技术与职责 |
|---|---|
| frontend | HTML/CSS/JS ES 模块，Nginx 静态页面与同源 API |
| backend | Python 3.11、FastAPI、SQLAlchemy、JWT |
| worker | Python 后台进程，使用 DB 的原子认领、租约与重试，输出 CSV |
| db | MySQL 8.0，存账号、版本、计算单和审计 |
| redis | Redis 7，通知 worker 尽快拾取，任务状态由数据库持久化 |

`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` 管理回环端口，`JWT_SECRET` 为签名密钥，`DB_PASSWORD` 为应用数据库口令，`DB_ROOT_PASSWORD` 为数据库 root 口令，`COMPOSE_PROJECT_NAME` 控制该栈的命名空间。

本地 Python 开发可用 `docker compose up -d db` 启动关系库，并另起一个仅绑定回环的 Redis。Compose 内的 Redis 通过容器网络连接。用 Python 3.11 安装 `backend/requirements.txt` 后，进入 backend 目录，设置 `DATABASE_URL`、`REDIS_URL`、`JWT_SECRET`、`ARTIFACTS_DIR`、`SEED_DEMO`，分别运行 `uvicorn src.main:app --reload`、`python -m src.worker`。ARTIFACTS_DIR 需已存在且由两进程共享。前端可使用 Compose Nginx 镜像并重建以加载修改，或用已有 Nginx 反向代理本地 Python 端口。

`backend/src/business/` 保存本题字段、生成器和算法，`backend/src/services/` 处理资源生命周期，`backend/migrations/` 是初始关系模式，`frontend/src/` 按页面、API、会话、组件、路由及样式组织。前后端枚举分别在 `backend/src/constants/workflow.py` 和 `frontend/src/constants/enums.js`。角色用于 JWT 路由与表单权限，计算状态用于队列与结果页，签审决定用于交接页、审计和签发导出。
